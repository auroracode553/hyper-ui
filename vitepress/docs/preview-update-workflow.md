# 预览更新与验收

VitePress 读取 vitepress/docs/ 中的权威 Markdown；手机中的 Compose 交互示例来自独立 Preview 产物。文档热更新不等于交互产物已经更新。Desktop/Wasm 仅用于文档验收，产品范围仍为 Android 手机竖屏 320–430dp。

## 文档与交互示例

只改 Markdown、文档排版或 Vue 工具栏时，已有文档服务可以刷新这些内容。Kotlin 组件、示例、主题或 Markdown 解析器改变后，维护者需要自行重新生成 Preview 产物。

手动执行说明：仅阅读文档可使用 vitepress/ 中的 npm run dev:doc。当前 npm run dev 是维护者的监听与构建流程，会启动 Gradle；请依据自己的运行约束选择。文档页面与预览按钮不会启动这些命令或安装依赖。

## 编译资源与并行范围

`preview/gradle.properties` 按本机 8 核 16 线程、约 32GB 内存配置：Gradle worker 上限为 16，Gradle 堆上限为 4GB，独立 Kotlin daemon 堆上限为 3GB。守护进程、构建缓存与 Kotlin/JS/多平台增量编译保持启用；配置缓存继续关闭。

Android 库与 Desktop Preview 的 JVM 代码生成设置 `-Xbackend-threads=0`，自动使用可用处理器数量。[Kotlin 官方说明](https://kotlinlang.org/docs/whatsnew1620.html#support-for-parallel-compilation-of-a-single-module-in-the-jvm-backend)中该参数仅适用于 JVM 后端。Wasm 不接收这个参数；16 个 worker 只允许可独立执行的任务并行，不能保证 Wasm 单任务的每个阶段都占满 CPU。

配置在下一次手动启动 Gradle 构建时读取，已开始的编译不会中途切换资源配置。无需清理已有增量缓存；如监听流程正在运行，可由维护者停止后手动重新启动。同一输出目录的构建继续串行提交，避免多个 Gradle 调用争用产物。

## 产物与状态

维护者可在允许构建的环境中先处理 Kotlin/Wasm 包锁，再运行 Preview 的 publishWasmToVitePress 任务。任务把生成产物复制到 vitepress/public/wasm-preview/，成功后写入 preview-ready.json。文档根据该文件的版本加载新 iframe。

维护者手动运行现有的 npm run dev 监听流程后，Gradle 的标准输出和错误输出会同步到终端及预览状态。手机区域每秒刷新依赖准备、Kotlin/Wasm 编译、链接优化、资源打包与发布的实际任务，展示本次构建和当前阶段耗时、当前任务及最新输出。长任务没有新输出时单独显示等待时长，进程心跳只证明仍在运行。阶段条不是编译百分比，不按耗时推算完成度。

编译期间手机区域显示进度，正文继续可读；旧产物不能作为当前源码的交互预览。成功发布后加载新版本，确认产物实际返回的组件 ID 与文档指定 ID 一致，再显示组件。未匹配、缺少身份信息或指定 ID 不存在时提示更新产物，不使用 Button 或其他示例补位。

编译失败时显示实际错误摘要，完整日志保留在维护者终端。主动结束监听时记录停止状态；超过 15 秒没有收到心跳时显示进度连接中断，不把残留的 compiling 状态当作仍在编译。重新检查只读取状态和重新加载预览，不启动 Gradle 或安装依赖。更新状态采集源码后，需要由维护者手动重启原监听进程。

状态文件采用异步串行写入，连续输出合并为最新快照。优先原子替换；Windows 暂时禁止替换时退避重试，仍被占用则尝试写回目标文件。读取端遇到不完整 JSON 保留上次状态。写入失败只记录提示并重试，不终止 Gradle 或文档进程；发布成功和停止前等待最终状态写入。

阶段 2/4 表示预览流程中的编译发布阶段，不是 Gradle 的任务完成比例。当前任务名称来自 Gradle 实际输出；单个 Kotlin/Wasm 优化任务没有可供此采集器读取的内部完成百分比，因此不按耗时推算百分比。

## 手机验收

1. 在组件页选择 320/350/390/430dp 宽度，检查长文案和禁用、聚焦、错误、加载与选中状态。
2. HyperList、HyperGroupedList 的列表应占满顶部控件下方的视口，滚动到末项；分段列表最后一组应能完整查看并操作。
3. 普通组件示例滚动整页；页面级列表独自滚动。不能出现固定 280/340dp 高度之后留大片空白，或外层与列表重复垂直滚动。
4. 点击重置应恢复当前示例的初始状态；切换宽度应保持内容可见，不通过缩放伪造手机尺寸。
5. 检查浅深色、LTR/RTL、实色表面，以及导航、弹窗、抽屉的顶部和底部安全区。
6. 展开最小调用和公开签名，核对 Props 的参数、类型、必填、默认值和作用五列。窄页面只在表格区域横向滚动。

## 长时间等待或资源失败

已有监听进程在运行时，先核对实际进程、终端日志、心跳和产物版本。状态文件存在不能证明任务仍在运行，也不能替代组件 ID、首帧和交互验收。只运行 npm run dev:doc 或使用独立 Wasm 开发服务器时，不会由文档页发起或采集 Gradle 编译；实时任务进度来自维护者手动运行的 npm run dev 流程。

若日志停在 Binaryen 依赖解析，维护者应检查实际下载地址、网络与仓库连通性。已有构建配置支持通过 HYPER_UI_BINARYEN_ARCHIVE_DIR 注入经校验的本地官方压缩包；该设置由维护者自行处理，不由组件文档或预览按钮安装工具。

本页只提供手动说明，不包含自动执行逻辑或一键启动脚本。
